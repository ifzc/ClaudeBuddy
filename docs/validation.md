# 验证范围

初次桌面验证环境：Windows 11 x64；飞书 8.2.0.73；微信 4.1.7.59；电脑系统时区为 America/Phoenix 对应的 Windows 时区。

## 自动验证

- 配置默认值互不共享；部分配置保留另一应用默认值；非法数据形状、时区和路径类型被拒绝。
- 飞书只选择 renderer；微信的 OCR、播放器和小程序进程不选择；不同控制器的子进程互不干扰。
- 使用独立 Python 子进程实际调用 Windows API，覆盖北京、亚利桑那和纽约的时区读数、一月/七月转换、UTC 不变及卸载后恢复。
- 两个真实测试进程同时使用不同的时区；恢复其中一个，另一个仍保持自己的时区。
- 使用实际 Tk 窗口和已注入时区的独立测试进程，关闭设置窗口后进程仍存活且时区保持不变；通过托盘回调重新打开窗口后时区仍保持不变。无桌面任务栏的 CI 环境验证最小化回退路径。
- 任务栏时区配置独立保存；北京与亚利桑那跨日、纽约夏令时开始/结束和 UTC 转换调用真实 Windows API，确认转换前后系统时区结构一致。

## v0.2.0 任务栏桌面验证

Windows 11 26H2、build 26300.9711 的主屏任务栏上执行 `tests/integration/taskbar_lifecycle.py`：已知时钟元素识别成功；显示层采用点击穿透和不抢焦点样式；设置窗口关闭后继续运行；实时切换至 UTC 生效；关闭后窗口销毁，系统时区仍为 `US Mountain Standard Time`。现有应用时区的四组原生测试及窗口生命周期测试继续通过。此测试不重启 Explorer、飞书或微信。
